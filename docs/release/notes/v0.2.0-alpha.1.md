# Axrail v0.2.0-alpha.1

> npm dist-tag: `next`  
> Runtime: Node.js >=22.13.0  
> Status: prerelease integration baseline for AI-native HMI / engineering-software adapters.

## Purpose

This alpha is the first installable npm baseline intended for real third-party HMI/configuration-software integration.

It packages the post-RC architecture work that was previously available only from Axrail `main`.

## Highlights

### Provider-bound Transactional Mutation

High-level durable ChangeSet execution is available through `HarnessRuntime.executeChangeSet()` with a `ProviderBoundTransactionExecutor`.

The effect provider and governed Adapter provider scope remain bound fail-closed.

### AI-native HMI integration contracts

`@axrail/hmi-adapter-kit` provides vendor-neutral HMI capabilities and normalized project/screen/component/binding contracts for private HMI adapters.

### Interactive Selection / Scoped Editing

`@axrail/adapter-sdk` and `@axrail/hmi-adapter-kit` include explicit Selection Context contracts for:

- current screen selection;
- single component selection;
- multi-component selection;
- region/box selection;
- blank-region placement intent.

The HMI/editor owns canvas interaction and hit testing. Axrail receives stable engineering target IDs plus optional geometry evidence.

### Headless Interaction SDK

New package:

```text
@axrail/interaction-sdk
```

It provides:

- `InteractionRuntime`;
- explicit Selection snapshot handling;
- Adapter + plugin Context composition;
- bounded untrusted-data Context envelopes;
- normalized interaction events;
- reversible typed Interaction Plugins.

Plugins may extend interaction/context/model registration but cannot replace or bypass ToolRuntime, Policy, Validation, Approval, TransactionRuntime or provider-bound execution.

### Model Registry and runtime switching

`@axrail/interaction-sdk` now includes:

- `ModelRegistry`;
- explicit per-turn `modelId`;
- constructor default model selection;
- model capability requirements;
- model provenance;
- reversible model registration through Interaction Plugins.

Model identity remains provenance, not engineering execution authority.

### Vercel AI SDK provider convergence

New package:

```text
@axrail/model-ai-sdk
```

The package adapts a Vercel AI SDK `LanguageModel` to Axrail `AgentModelProvider`.

The bridge performs exactly one model generation step and supplies Tool schemas without `execute` handlers. Engineering Tool calls always return to:

```text
Axrail AgentLoop
  -> ToolRuntime
  -> Policy / Approval / Audit
  -> Tool effect
```

The existing `@axrail/model-openai-compatible` package remains available as a lightweight/reference compatibility path.

## HMI integration install

Recommended minimum HMI-side install:

```bash
pnpm add \
  @axrail/harness@0.2.0-alpha.1 \
  @axrail/interaction-sdk@0.2.0-alpha.1 \
  @axrail/model-ai-sdk@0.2.0-alpha.1 \
  @axrail/hmi-adapter-kit@0.2.0-alpha.1 \
  @axrail/adapter-sdk@0.2.0-alpha.1
```

Install the Vercel AI SDK provider package required by the product separately.

## Known alpha boundaries

- Real proprietary HMI vertical-slice validation is still pending receiving-product API/SDK details.
- Persisted multi-turn conversation continuation is not yet frozen as a public Interaction SDK contract.
- Automatic model routing/fallback is intentionally not included.
- `@axrail/model-ai-sdk` is provider infrastructure only; Axrail remains authoritative for engineering Tool execution.


## npm dist-tags and package-page display

This prerelease is published with:

```text
next -> 0.2.0-alpha.1
```

It intentionally does not move `latest` and does not overwrite the historical `rc` dist-tag.

Therefore an npm package page may still show `0.1.0-rc.1` as its default visible version even though `0.2.0-alpha.1` is published and installable.

Verify the prerelease directly:

```bash
npm view @axrail/harness@0.2.0-alpha.1 version
npm view @axrail/interaction-sdk@0.2.0-alpha.1 version
npm view @axrail/model-ai-sdk@0.2.0-alpha.1 version
npm view @axrail/harness dist-tags
```

The release is lockstep across all 17 public packages. The two packages that are new relative to RC1 are `@axrail/interaction-sdk` and `@axrail/model-ai-sdk`; the other 15 public packages were also published at `0.2.0-alpha.1`.

For product integration, prefer exact versions over `@next` so subsequent prereleases cannot silently change the resolved Axrail baseline.
