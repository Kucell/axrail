# Axrail v0.1 Package Build Strategy Analysis

Status: **approved and implemented**.

Decision `D-v01-package-build-strategy` selected TypeScript project references/composite builds with native `tsc -b`, NodeNext ESM output and declaration emit for the v0.1 package graph.

## Repository facts behind the decision

Axrail's repository shape favors native TypeScript emit over default package bundling:

- TypeScript target is ES2022.
- Module mode/resolution is `NodeNext`.
- Runtime packages declare `"type": "module"`.
- Source already uses `.js` import specifiers appropriate for NodeNext emit.
- Harness, Adapter SDK, Tools, Transactions, Events and the other packages are intentional architecture/public API boundaries rather than implementation chunks to flatten.
- The public packages are libraries/SDKs, not a browser application bundle.
- External runtime dependencies such as `@modelcontextprotocol/client` should stay external rather than being embedded into an Axrail bundle.
- Declaration/module structure matters to Adapter and library authors.
- The CLI can be normal Node ESM with a shebang/bin entry; it does not require a single-file bundle for v0.1.

## Considered alternatives

### Per-package bundler

A bundler such as tsup could provide convenient JS/declaration generation and future target-specific packaging, but making it the default v0.1 architecture would add another transformation layer and could obscure package/dependency boundaries that Axrail intentionally exposes.

Bundling remains a valid future choice for a standalone CLI, browser/edge artifact, or deployment-specific package.

### TypeScript project references — selected

The selected shape is:

```text
package/src/*.ts
      ↓
tsc -b project graph
      ↓
package/dist/*.js
package/dist/*.d.ts
package/dist/*.map
```

Advantages for Axrail:

- preserves ESM module structure;
- preserves declaration structure;
- keeps workspace/public package boundaries explicit;
- lets TypeScript enforce dependency build order;
- avoids an unnecessary bundler/runtime transform;
- works naturally with Node 20/22/24 and the current source style.

## Implemented structure

The repository now contains:

- `tsconfig.build.base.json`
- root `tsconfig.build.json`
- per-public-package `tsconfig.build.json`
- root `pnpm build` / `pnpm clean`
- per-package build/clean scripts
- `dist` package entry points and declaration entry points
- project references matching the approved 15-package dependency graph

`@axrail/core` remains outside the supported public build graph.

## Release verification

```text

65 behavioral tests

clean npm consumer install

```

The prepared lockstep candidate version is `0.1.0-rc.1`.

## Future bundling rule

Adding a bundler later should be target-specific and must not silently change the supported package/API semantics. A standalone executable or browser build may bundle dependencies; the canonical SDK packages remain structurally versioned package boundaries unless a future architecture decision changes that policy.
