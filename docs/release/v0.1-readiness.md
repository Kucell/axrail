## Release blockers

### 1. Package build and publish artifacts — BLOCKED ON ARCHITECTURE DECISION

Current packages are optimized for monorepo development rather than npm consumption:

- package versions are still `0.0.0`
- packages remain `private: true`
- some packages point exports/types directly at TypeScript source
- package metadata is not yet consistent across the workspace
- there is no common JavaScript/declaration build output
- there is no clean install/import smoke test for packed artifacts
- the CLI does not yet ship as a standalone installed binary

Tracked by Issue #15.

The build strategy is intentionally not selected implicitly. The development architecture decision `D-v01-package-build-strategy` must be resolved before adopting a package build architecture.

### 2. Public package and API surface — OPEN

Before publishing, define which packages are public and which symbols are intentionally supported in v0.1.

This is not a v1.0 compatibility freeze. v0.1 may remain unstable, but accidental/internal exports should not become public by default.

Tracked by Issue #17.

### 3. Compatibility/release CI — IN PROGRESS

Current CI validates TypeScript and cross-package behavior. Release hardening should also validate:

- the supported Node major range
- built/packed artifacts once #15 is implemented
- clean consumer install/import behavior

Tracked by Issue #16.

### 4. Versioning and release automation — OPEN

The repository does not yet have a complete release/version/changelog workflow for a tagged v0.1 release.

Tracked by Issue #18.

## Release principle

A tagged v0.1 release should mean more than "the source tree passes tests".

At minimum, a release candidate should satisfy:

```text
Functional scope complete
        ↓
Intentional public package/API surface
        ↓
Reproducible build artifacts
        ↓
Pack/install/import smoke test
        ↓
Supported runtime compatibility CI
        ↓
Version/changelog/release process
        ↓
Tagged v0.1 release
```

Until these gates are complete, the repository should describe itself as a draft/pre-release implementation even though the functional v0.1 scope is complete.
