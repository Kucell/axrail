## Production storage/audit guidance — DOCUMENTED

`JsonlEventStore` is an embedded/reference durable provider, not a multi-process/compliance-grade production audit database. The default `best_effort` profile is a development/embedded default; applications needing durable pre-effect/pre-commit evidence should explicitly select a strict audit profile and a suitable EventStore.

## Publication automation — REPOSITORY SIDE COMPLETE

Issue #18 now has repository-side mechanics implemented:

### One-time first publish

`.github/workflows/release-bootstrap.yml`

- complete verification before approval;
- immutable verified tarballs uploaded before the publish gate;
- protected `npm-release-bootstrap` Environment;
- explicit `RELEASE_GUARD=enabled` requirement;
- short-lived environment `NPM_TOKEN` only for the bootstrap;
- public `rc` dist-tag and provenance;
- same tarballs are published that passed verification.

### Subsequent releases

`.github/workflows/release-stage.yml`

- complete verification before approval;
- protected `npm-release` Environment plus `RELEASE_GUARD=enabled`;
- GitHub OIDC Trusted Publishing, no long-lived npm write token;
- `npm stage publish` so packages remain non-public until npm maintainer 2FA approval.

### GitHub release finalization

`.github/workflows/release-finalize.yml`

- protected `github-release` Environment plus `RELEASE_GUARD=enabled`;
- exact verified commit SHA input;
- verifies all 15 npm versions are publicly visible before any tag is created;
- requires a prepared release-notes file;
- creates annotated `v<version>` tag and GitHub Release only after registry verification.

Operational details: `docs/release/npm-publication.md`.
